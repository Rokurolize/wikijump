### P1 - invocation grammar and scalar interpretation

- The site owner can control whether Wikidot sends outgoing pingbacks for links from the site; the high-level source establishes the existence of this site-level control but not additional accepted values.

### P2 - parser stage, nesting, and composition

- Pingback control is site runtime configuration, not link/parser grammar; link syntax is parsed independently.

### P3 - lifecycle, persistence, import, and round trips

- The setting persists at site level and applies to subsequent eligible page activity without rewriting page source.

### P4 - actors, permissions, visibility, and privacy

- Only authorized site administrators may change outgoing-pingback policy. Pingback payloads MUST NOT disclose private page content or actor secrets.

### P5 - selection, ordering, counting, and pagination

- No ordering/pagination semantics are defined. Duplicate/retry behavior is a delivery concern, not a page query.

### P6 - HTTP, API, URL, Ajax, feed, and navigation contracts

- When enabled, pingback delivery is an outbound network side effect to linked endpoints; when disabled, no outgoing pingback request may be generated by this feature. Exact endpoint/XML body requires live observation before implementing a Wikidot-specific sender.

### P7 - DOM, CSS, resources, interaction, and geometry

- No page DOM is required for an outgoing pingback beyond any Site Manager control; public links render normally whether pingbacks are enabled or disabled.

### P8 - temporal behavior, failure atomicity, limits, and resource bounds

- Network failure MUST NOT roll back or corrupt the page edit that triggered an optional pingback. Unobserved retry/backoff behavior MUST remain conservative and bounded rather than guessed.
