# Open43 settings and browser closure audit referents

| Source | Purpose | Concrete Referent | Role | Ordering | Candidate Term | First-Use Definition |
| --- | --- | --- | --- | --- | --- | --- |
| Current source and public behavior test | Separate implemented source from an executed acceptance verdict | An acceptance subrow whose implementation and evidence-backed public-seam test both exist at the frozen source identity | State | Before candidate execution | `source_ready` | `source_ready` means the source implementation and an evidence-backed public-seam test exist; it does not claim that the final candidate passed. |
| Current source audit | Keep a known implementable source omission actionable | An acceptance subrow with sufficient evidence but a missing implementation, public-seam test, route, cache identity, or candidate harness | State | Before candidate execution | `needs_source` | `needs_source` means evidence is sufficient but source work is still required before candidate acceptance can run. |
| Exact merged candidate | Reserve runtime-dependent claims for an identity-bound run | An acceptance subrow whose result depends on the final Wikijump tree, FTML pin, locks, migrated database, compiled pages, immutable assets, served route, or browser | State | After source freeze | `candidate_required` | `candidate_required` means the exact final candidate must produce the named public runtime or browser artifact before the subrow can pass. |
| Missing live contract | Prevent plausible but invented compatibility behavior | An acceptance subrow whose observable Wikidot behavior is not established by durable live evidence | State | Before source implementation | `blocked_evidence` | `blocked_evidence` means the subrow remains actionable but must not be implemented or accepted until the listed live behavior is observed. |
| DOMContentLoaded capture | Prove what a user can see before resources and hydration settle | The immutable public browser observation captured immediately after DOMContentLoaded, with its own candidate and artifact identities | Record | First browser interval | `initial_paint_artifact` | `initial_paint_artifact` is the identity-bound DOM, style, geometry, request, and console observation captured at the immediate DOMContentLoaded interval. |
| Settled capture | Prove the final state without substituting it for first paint | The immutable public browser observation captured after fonts, images, styles, and required interactions settle, with its own candidate and artifact identities | Record | Second browser interval | `settled_artifact` | `settled_artifact` is the identity-bound DOM, style, geometry, request, and console observation captured only after the declared resource and interaction completion policy succeeds. |
| Shared Settings candidate runner | Keep one executable authority for reversible Settings browser acceptance | The existing `C_SETTINGS_CANDIDATE` command whose fixed nine-case denominator also exercises the legacy administrator route | Means | After source freeze and before any acceptance claim | `settings_candidate_command` | `settings_candidate_command` refers to the shared nine-case command; no separate legacy-route browser command exists. |
| Finalized Deepwell renderer identity | Keep the audit aligned with the cache epoch served by the integrated source | Renderer epoch 6 and the exact finalization source identity that invalidates pre-freeze compiled artifacts | State | Before candidate capture | `renderer_epoch_finalization` | `renderer_epoch_finalization` records the current completed epoch-6 cache identity and requires no later integration reconciliation. |
