# Deviation: runtime module residual finalization

- Shim: `RenderService::finalize_runtime_module_residuals` in `deepwell/src/services/render/runtime_modules.rs`, invoked by the runtime expansion pipeline in `deepwell/src/services/render/service.rs`.
- Reason it lives in Wikijump: Wikijump must decide whether a module left after runtime expansion is an intentionally preserved runtime-owned shape or a page-source-only unavailable module. That disposition depends on Wikijump's bounded module passes and cannot be inferred from the module name alone before those passes run.
- Why FTML is not yet sufficient: FTML `src/parsing/rule/impls/block/blocks/module/rule.rs` immediately converts every syntactically valid unregistered module into its generic unknown-module error. It has no typed generic module node or caller-supplied disposition hook that lets Wikijump preserve a residual runtime module while standalone FTML keeps the generic error behavior.
- Evidence: FTML pin `902e72a2ff261b7af42402734b2f8b659e6a294a`; Wikijump integration tests `anonymous_page_and_site_utility_modules_match_frozen_safe_states`, `imported_redirect_noredirect_renders_live_error_block`, `loginstatus_page_source_matches_live_unavailable_module`, `layout_only_modules_page_source_match_live_unavailable_module`, `pages_by_tag_module_renders_empty_list_and_preserves_unevidenced_forms`, `newpage_over_budget_template_list_remains_literal`, and `newpage_modules_after_the_per_render_budget_remain_literal` in `deepwell/tests/page.rs`.
- FTML backlog decision: this is newly accepted Wikijump-side debt. The missing FTML capability is a typed generic delayed-module representation, or an equivalent caller disposition hook, that preserves exact source and body ownership until the runtime consumer decides whether to render, preserve, or reject the module.
- Migration condition: FTML exposes that delayed generic module boundary, standalone `Layout::Wikidot` still renders the live generic unknown-module error by default, and Wikijump can remove the name-scoped finalization pass without changing the six cited integration results.
- Owner: Rokurolize.
- Review trigger: every FTML pin bump that changes module parsing, and any FTML work that adds a generic or delayed module node.
