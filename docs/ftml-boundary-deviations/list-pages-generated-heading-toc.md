# Deviation: ListPages-generated heading TOC suppression

## Shim

`suppress_generated_list_pages_heading_toc` in
`deepwell/src/services/render/list_pages/rendering_support.rs` marks active
heading lines in ListPages-generated fragments with FTML's existing no-TOC
heading syntax before the final page parse. It applies only to fragments whose
ListPages provenance is known by the runtime and leaves headings inside
literal owners unchanged.

## Reason it lives in Wikijump

Wikijump owns ListPages template expansion and therefore knows which heading
source was generated by a delayed runtime query. Live Wikidot renders those
headings at their authored level but does not register them as page headings:
they have no `tocN` ID, consume no authored heading number, and create no
outer-TOC entry. Ordinary authored headings retain the normal FTML path.

## Why FTML is not yet sufficient

The pinned FTML interface
(`a8fcd3dce089aefd6a9a3619116d4777c9ebd7cc`) has the correct syntax-rendering
primitive for a visible heading excluded from TOC registration (`+*` through
`++++++*`). Its delayed ListPages representation does not expose a typed
generated-fragment parse mode through which Wikijump can preserve that
runtime provenance across the outer page parse. The bounded source marker is
therefore required until that interface exists.

## Migration condition

Remove this source marker when FTML exposes a typed ListPages-generated
fragment or equivalent provenance-aware parse API that can render heading
syntax without registering page heading IDs or TOC entries. Migration must
retain literal ownership, output-budget accounting, inline heading contents,
and authored heading numbering before and after generated fragments.
